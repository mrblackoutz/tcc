## Resultado publicado

G3c habilita o transporte real somente por profile e modo explícitos:

- a chave local é montada por arquivo exato e somente leitura apenas no `llm-client-g3c`;
- o runner não recebe chave, proxy, credencial do ERP ou rota externa;
- o cliente não participa da rede do ERP e não possui saída direta;
- somente o proxy participa da rede externa e permite `CONNECT api.deepseek.com:443`;
- o request sintético mantém `deepseek-v4-flash`, *thinking* desligado, temperatura zero, JSON mode e ausência de streaming;
- qualquer tentativa iniciada cria marcador local e proíbe retry automático;
- sucesso só pode ser declarado após manifesto saneado, validações e varredura de logs.

O destino permitido foi alcançado, mas o provedor respondeu HTTP 402. Isso comprova conectividade até o endpoint dentro da fronteira aprovada, não uma inferência aceita. Não foram observados modelo retornado, tokens, latência de inferência, saída estruturada ou competência benigna.

## Próximo gate

Após disponibilizar crédito ou saldo no provedor, o operador deve solicitar uma nova execução. O marcador ativo precisa ser arquivado com verificação de hash antes da tentativa. O script fará uma única chamada, sem retry, e G3-05 somente poderá passar para `DONE` se o manifesto saneado comprovar resposta tipada, modelo retornado, uso, latência e hashes e a varredura de logs não encontrar segredo ou payload proibido.
