## Incremento executável M1/G1

Conforme autorizado por DEC-014 e DEC-015:

1. **Odoo 19.0 Community:** imagem Docker multi-stage construída localmente a partir da origem oficial (`https://github.com/odoo/odoo.git`) no commit imutável fixado `a4b877245c9cb5e3d7152d1593a518170f115ca1`. A imagem possui labels OCI auditáveis (`org.opencontainers.image.revision`, `source`, `version`, `base.name`, `platform`) e comprovação interna em `/opt/odoo/.tcc-source-commit`.
2. **PostgreSQL 18:** serviço de banco fixado pelo digest imutável `postgres:18@sha256:7341002d2b8c7c5bdd7542a671a95b36196c0b5b888daf454ae4fc33ba5346d7`, com volume mapeado para `/var/lib/postgresql` (estrutura padrão do PostgreSQL 18+). Sem portas publicadas fora da rede interna do Compose.
3. **Gateway JSON-2 (`tcc_gateway`):** cliente Python com sanitização estrita de credenciais em logs/representações/exceções, serialização canônica determinística (`canonical_json_bytes`, `canonical_json_sha256`) e suíte de 19 testes unitários aprovados (`pytest -ra`).
4. **Scripts operacionais:**
   - `scripts/new_local_env.ps1`: gera `.env`, `.runtime/odoo.conf` e segredo local sem exibir valores sensíveis.
   - `scripts/build_odoo_image.ps1`: constrói a imagem Odoo, verifica a revisão contra o commit esperado e atualiza o lockfile.
   - `scripts/smoke_test.ps1` e `scripts/smoke_test_gateway.py`: realizam bootstrap completo, inicialização limpa de 50 módulos (`base, l10n_generic_coa, account, purchase`), validação do endpoint HTTP `/web/health`, geração de chave RPC, operações CRUD via JSON-2 (`search_read`, `create`, `read-back`) e reset determinístico via `docker compose down -v` com confirmação de remoção de volumes.
